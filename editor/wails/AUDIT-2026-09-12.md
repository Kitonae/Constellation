**Constellation desktop app audit — 12 September 2026**

The main weakness is disagreement between the editor, web outputs and native outputs about the same document and transport state. The components have useful structure and the existing tests pass, but important show operations still produce lost edits, blank outputs or incorrect playback. I found **16 actionable issues**, of which **11 were reproduced with isolated behavioral probes**. The other five follow directly from the reviewed code and were not exercised on live output hardware.

Scope: the active `editor/ui`, `editor/wails` and `editor/renderer` stack, including React interactions, persistence, output lifecycle, HTTP/SSE, DX12 presentation, media loading, decoding, audio, shaders, NDI and build/test architecture. The marketing website was outside this desktop-app audit. Final source reference: `f3772d6de1b7cf1099968490cd57d8cc19ecaf5b`. Renderer/thumbnail commits arrived during the audit; final findings and checks include them. The generated-binding modifications already present in the workspace were preserved. This audit changed no application source.

**Priority definitions:** P1 should be addressed before relying on the affected workflow for a show; P2 is a concrete correctness defect to address next. There are six P1 and ten P2 findings.

**Findings, ordered by priority**

1. **P1 — The sidecar serves arbitrary accessible local files to unauthenticated callers.** Path validation checks drive-letter syntax, not whether a file belongs to the project or was selected by the user. `/fs/` also returns `Access-Control-Allow-Origin: *`. A probe requested an unregistered synthetic text file with an unrelated Origin and received HTTP 200, the marker contents and wildcard CORS. Any client able to reach the sidecar can use this interface; browser restrictions on access to localhost may affect a particular web-origin attack, but are not an application authorization boundary. Add per-session authentication, restrict allowed origins/hosts, and serve registered asset handles or explicitly authorized paths. Review SSE, status and thumbnail routes under the same policy. Evidence: [fileloader.go](C:/src/Constellation/editor/wails/fileloader.go:45), [validation](C:/src/Constellation/editor/wails/fileloader.go:24), [routes.go](C:/src/Constellation/editor/wails/routes.go:12). **Reproduced with a temporary marker file.**

2. **P1 — Web output windows cannot resolve normal imported local media.** The sidecar window is a plain browser context, so the store's `isWails()` initialization does not run there. The file resolver starts with an empty base URL, and DisplayWindow never initializes it from its own sidecar origin or an explicit handshake. A normal `file:///C:/media/clip.mp4` resolves to an empty string, leaving image/video output blank. Initialize output capabilities and the asset base before accepting a snapshot, or send resolved asset URLs. Evidence: [store.js](C:/src/Constellation/editor/ui/src/store.js:25), [uri.js](C:/src/Constellation/editor/ui/src/media/uri.js:171), [DisplayWindow.jsx](C:/src/Constellation/editor/ui/src/components/DisplayWindow.jsx:19). **Resolver failure reproduced in a simulated sidecar window.**

3. **P1 — Native playback ignores source in-points, so splitting a video restarts its content.** The store correctly gives the right half of a split a later `in_seconds`. The native scene model does not retain that field, and both the video and audio paths request `currentTime - clip.start`. Split a video at 5 seconds: one second into the right half, the web render model requests source time 6, while the native code requests source time 1. Parse source offsets into the native model and use one source-time calculation for video, audio and prefetch. Evidence: [split operation](C:/src/Constellation/editor/ui/src/store.js:584), [native parser](C:/src/Constellation/editor/renderer/src/scene.cpp:82), [video time](C:/src/Constellation/editor/renderer/src/app.cpp:439), [audio time](C:/src/Constellation/editor/renderer/src/app.cpp:342). **Code-confirmed; no live media comparison.**

4. **P1 — New/Open replaces the document without resetting the authoritative clock.** Both actions set the store's displayed time to zero but leave the MediaSession clock and playing state intact. The probe played at 42 seconds and created a new project: UI time became 0, clock time remained 42, and `playing` remained true. Subsequent ticks restore the old time; snapshots already use that clock. Stop and reset transport as part of an atomic document replacement, before notifying outputs. Evidence: [loadProject/newProject](C:/src/Constellation/editor/ui/src/store.js:195), [snapshot time source](C:/src/Constellation/editor/ui/src/store.js:1031). **Reproduced.**

5. **P1 — Open Show discards unsaved changes without confirmation or an undo path.** New Show and menu Quit have dirty checks, but the file-open handler directly replaces the project and clears its history. The probe opened another JSON document after an edit: the new project loaded, no confirmation appeared, and undo history became empty. Native window close also has no application-specific dirty guard in the reviewed window setup. Route Open, New and native close through a shared document lifecycle; confirm before replacement and support cancel. Evidence: [open handler](C:/src/Constellation/editor/ui/src/App.jsx:407), [history reset](C:/src/Constellation/editor/ui/src/store.js:210), [window setup](C:/src/Constellation/editor/wails/main.go:78). **Open data loss reproduced; native-close omission confirmed by source review.**

6. **P1 — Adding native outputs duplicates local audio playback.** Go launches a process per screen and broadcasts the complete timeline to all processes. Every process opens audio players for every active video and selects the same default WASAPI endpoint. Two native screens therefore produce two independently timed instances of the soundtrack, including clips outside a screen's visual crop. Give audio an explicit single owner or route audio to a configured output/device independently of screen count. Evidence: [process-per-screen launch](C:/src/Constellation/editor/wails/renderer.go:85), [audio iteration](C:/src/Constellation/editor/renderer/src/app.cpp:330), [default endpoint](C:/src/Constellation/editor/renderer/src/audio_player.cpp:123). **Code-confirmed; not measured with speakers.**

7. **P2 — The first native sink opened mid-show misses transport state.** `addSink()` sends only a snapshot. Native serialization removes snapshot time/playing, and the native sink's snapshot handler sends no time or control. The SSE hub cannot replay transport that was never sent while no native sink existed. The probe added the first native sink while playing at 42 seconds and observed only a project snapshot. A paused launch stays at zero; a playing launch receives later ticks but no play command, leaving native audio paused. Attach each sink with an explicit current time and transport state. Evidence: [session.js](C:/src/Constellation/editor/ui/src/media/session.js:167), [sink.js](C:/src/Constellation/editor/ui/src/media/sink.js:196), [serialization](C:/src/Constellation/editor/ui/src/store.js:1065). **Reproduced with a recording native sink.**

8. **P2 — Web outputs ignore their screen's stage position.** `screenId` is used for lifecycle messages, but rendering never looks up that screen's transform. All web screens compose around the same origin. In the probe, a 100-pixel clip centered on a screen at X=500 appeared at left=1410 instead of 910 in a 1920-pixel output. Native output does subtract the screen position. Apply a shared world-to-screen transform to the web render list. Evidence: [DisplayWindow layout](C:/src/Constellation/editor/ui/src/components/DisplayWindow.jsx:138), [native offset](C:/src/Constellation/editor/renderer/src/app.cpp:508). **Reproduced through DisplayWindow DOM rendering.**

9. **P2 — Left-edge trimming moves the source start incorrectly.** `trimClip()` moves timeline start and shortens duration while preserving `in_seconds`; it recomputes the source out-point from the old in-point. Trimming three seconds off the left of a ten-second video still shows source time 0 at the new start, instead of source time 3. Update source in/out together with placement timing, with source-bound constraints. This is separate from the native parser issue and also affects web rendering. Evidence: [trimClip](C:/src/Constellation/editor/ui/src/store.js:490), [trim commit](C:/src/Constellation/editor/ui/src/components/Timeline.jsx:445). **Reproduced through the actual store and render model.**

10. **P2 — Relaunch/Re-open does not stop an existing renderer.** The Inspector deletes the previous-screen record; Re-open Displays clears the entire map. That prevents the main effect from taking its close-before-open branch. The native manager rejects the next open with “renderer already running.” The probe recorded `open` only, instead of `close, open`. Own restart as an awaited lifecycle operation and protect asynchronous completions with a generation token. Evidence: [Inspector restart effect](C:/src/Constellation/editor/ui/src/App.jsx:383), [Re-open Displays](C:/src/Constellation/editor/ui/src/App.jsx:435), [duplicate-process rejection](C:/src/Constellation/editor/wails/renderer.go:89). **Reproduced with the actual App effects and a simulated process bridge.**

11. **P2 — Relinking an image leaves the old image and dimensions on stage.** Viewport metadata is keyed by asset ID and skips any populated entry. Relinking intentionally keeps that ID, so its new URI never invalidates the cached source. DisplayWindow uses the same ID-only check. The hook probe retained the old source after receiving a new URI. Key derived data by asset ID plus URI/revision, clear it when documents change, and propagate invalidation to outputs. Evidence: [useImageMetaLoader.js](C:/src/Constellation/editor/ui/src/hooks/useImageMetaLoader.js:24), [DisplayWindow cache](C:/src/Constellation/editor/ui/src/components/DisplayWindow.jsx:102). **Stage hook reproduced; matching output cache confirmed by source.**

12. **P2 — Valid filenames containing percent signs fail to load.** Go's request URL path is already decoded, but FileLoader calls `PathUnescape` again. A real temporary file named `100% done.png`, requested with proper URL encoding, returns HTTP 400 because the second pass treats `% d` as an escape. Decode exactly once and retain tests for literal percent signs, encoded-looking names, spaces and Unicode. Evidence: [fileloader.go](C:/src/Constellation/editor/wails/fileloader.go:56). **Reproduced.**

13. **P2 — Native output and NDI include diagnostics by default.** `m_showDebug` defaults to true in all build configurations. The HUD is composited onto the back buffer before NDI capture, so a new native output exposes frame graphs, filenames and timing to the audience. F3 is only a manual per-process workaround. Default diagnostics off and separate operator overlays from clean output capture. Evidence: [default](C:/src/Constellation/editor/renderer/src/app.h:156), [HUD composition](C:/src/Constellation/editor/renderer/src/app.cpp:566), [NDI capture ordering](C:/src/Constellation/editor/renderer/src/app.cpp:682). **Code-confirmed.**

14. **P2 — Blur is editable and visible in web preview but has no native effect.** The Inspector exposes blur and the native app fills `blur_radius`, but neither native shader implements it. The shader explicitly describes the missing offscreen passes. Implement the effect or expose renderer capabilities in the UI so an operator can see that the selected output cannot reproduce it. Evidence: [effect controls](C:/src/Constellation/editor/ui/src/components/inspector/constants.js:36), [native effect dispatch](C:/src/Constellation/editor/renderer/src/app.cpp:525), [shader](C:/src/Constellation/editor/renderer/shaders/effects_ps.hlsl:5). **Code-confirmed.**

15. **P2 — The 3D screen geometry applies scale twice and ignores pixel aspect.** Its plane geometry uses `scale.x/scale.y`, and its parent group applies the same scale again. A scale of two creates four times the width; a default 1920×1080 screen appears as a square because pixels are not used. Derive base dimensions from a documented pixel-to-world conversion, then apply the transform once. Evidence: [Viewport.jsx](C:/src/Constellation/editor/ui/src/components/Viewport.jsx:49). **Code-confirmed.**

16. **P2 — Opacity keyboard stepping jumps to an endpoint.** Opacity config uses `step: 1` with `displayScale: 100`, while NumberInput multiplies the step by displayScale again. A single ArrowUp at 50% emits 100%, rather than 51%. Define whether step values are stored units or displayed units and apply that rule consistently to arrows and scrubbing. Evidence: [opacity configuration](C:/src/Constellation/editor/ui/src/components/inspector/constants.js:25), [NumberInput stepping](C:/src/Constellation/editor/ui/src/components/inspector/NumberInput.jsx:71). **Reproduced with the actual React control.**

**Architecture assessment**

The separation between editor UI, local service and native process is useful. The frame-context ring, fence-retired resources, background video loading, decoder frame pool and CPU regression tests are sensible foundations. The undo system uses immutable document references, and common menu, dialog and shortcut components reduce UI duplication. A full rewrite is not warranted by this audit.

The following changes would address the causes shared by several findings:

| Area | Current design and consequence | Recommended direction |
| --- | --- | --- |
| Document contract | The store edits `tracks[].media[]`; web output migrates to `tracks[].clips[]` on evaluation; C++ implements another parser. The store also holds both `project.scene` and `scene`, which can diverge. | Adopt one versioned document contract, validate it on load, migrate once, and share canonical fixtures across JS and C++. Keep one authoritative scene. |
| Rendering semantics | Stage, web output and native output independently evaluate timing, transforms and effects. The stage uses static video posters; its clock hook updates visibility, not moving video or fade opacity. | Define a render specification for source time, active interval, crop, sizing and effects. Test identical fixtures across consumers and state output capabilities explicitly. |
| Transport | Browser `requestAnimationFrame` advances presentation time; C++ only updates time when SSE events arrive. A stalled UI clock stalls native visual time while audio has its own device clock. | Anchor playback to monotonic transport state in the service/native layer and let each renderer advance locally, with periodic correction and explicit pause/seek messages. Test UI stalls and output reconnects. |
| Output ownership | React effects manage async process starts, window handles, sink registration and status through several maps/sets. Restart paths bypass teardown and pending operations have no cancellation generation. | Introduce one output controller with desired state, observed state, serialized per-screen operations and stale-result rejection. Keep React as a view of that state. |
| Resource budgeting | Each native process receives every asset and evaluates/decodes the full scene. Images are eagerly prefetched. Thumbnail cache misses can launch simultaneous decoder processes without in-flight deduplication or a concurrency cap. | Establish process, decoder, texture and thumbnail budgets; deduplicate work and preload only relevant media. Measure multiple 4K outputs before increasing feature scope. |
| Reliability and observability | SSE drops non-time events when its 64-slot queue fills; no sequence/acknowledgement detects divergence. Native FPS is calculated but `reportFPS()` has no caller. Several async failures are swallowed or only logged. | Keep the latest document snapshot, preserve ordered control, detect resynchronization needs, publish measured FPS and error states, and distinguish connection, decode and presentation health. |
| Frontend cost | The production build has a 1.36 MB minified JS entry and a 5.37 MB icon font. App and DisplayWindow share an eager entry including the 3D/UI dependency graph. | Split editor and output entry points, lazy-load 3D tools, subset icons, and cache timeline migration/topology construction independently of playback time. |
| Verification and delivery | Existing tests focus on local algorithms and basic empty-editor interactions. The only checked-in workflow builds the website. The package task builds the shell; native renderer/runtime assembly remains manual. | Add desktop CI for Go, UI, native regression and cross-layer fixtures. Assemble and smoke-test a complete package on a machine without development paths or SDK installations. |

Additional frontend concerns: property labels are generally sibling text rather than associated input labels, so many Inspector fields lack accessible names. Output view remains a placeholder. These are usability and completeness issues beyond the sixteen correctness findings above.

**Repair order**

First fix document replacement/dirty guards and the sidecar file boundary. Next repair local web asset resolution, native source timing and transport attachment, then establish single ownership of audio. Follow with crop/trim/relink/relaunch correctness and clean native output defaults. Add cross-layer regression fixtures as each issue is repaired; use those fixtures to guide schema and lifecycle consolidation before undertaking broader refactoring.
